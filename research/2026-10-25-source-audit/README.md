验证日期：2026-10-25。阶段：需求与网页设计；尚未接入正式 App。

第 64 轮更新见[2026-10-26 顺序验证](../validation-sequence-2026-10-26.md)：本轮原先空的马匹查询参数与公开客户端要求不匹配，改为逐马记录 ID 和 YYYYMMDD 日期后，已取得一匹马的六项及此前五场。旧空响应保留为当时请求的证据，不能据此判断源数据没有这些字段。另新增日本真实赛前存档及五个备用地区赛果样本；未来更新与全年度覆盖仍未通过。

第 63 轮补充见[后续验证](../2026-10-25-source-followup/README.md)：新增 JAIRS 英文年度目录到未来有马条件页的路径，以及 ERA 11 匹完整名次与原始 SP。下方矩阵保留第 61 轮当时结果，ERA 和日本英文资料的最新进展以补充记录为准；原日文受限路径、赛前赔率与长期稳定性仍未验证。

结论：部分来源已经可以不经过浏览器取得具体字段，NAR 也验证了一条首页到未来赛事的发现路径。**目前不能承诺所有地区完整覆盖、赛前赔率稳定可用，或未来赛事公布后一定能自动更新。** 单次成功、历史赛果重取与跨发布阶段更新是三件不同的事。

## 方法与证据边界

- 普通 urllib GET 访问 21 个已知官方页面，各一次、最多两个并发：14 个 HTTP 200、7 个 HTTP 403。这个比例只是本次页面访问结果，不是赛事覆盖率。
- 复用本地已检查的 HTML 解析器和港马会公开前端查询。无浏览器、登录、Cookie、访问限制绕过、重试、接口枚举或模式探测；没有执行下载的 JavaScript。
- 港马会另有四项公开只读查询：赛事列表、列表返回的赛日、返回马匹 ID 的资料、旧 Cox Plate 赛果。前两份成功响应在本地解析中断后复用，没有重复请求；恢复记录标记为 `reused_saved_response`，未编造原请求时间。
- NAR 首页返回的真实 href 被跟随一次，取得未来 JBC Classic 页面。所有原始响应、请求参数、哈希和可用获取时间保存在本文件夹。
- 使用 `check_saved_fields.py` 离线检查，输出 `field-checks.json`；同样的检查代码及执行输出见 `source-field-checks.ipynb`。它们是当前样本检查，不是生产采集器。

## 有效的字段检查

- NAR：以马号、马名核对 14 条名单，以来源马匹 ID 检查唯一性；保留除外，不把它当第 14 名。单胜派彩 170 円不能补成所有马的赔率。
- 香港盃：7 条赛果马号唯一、名次 1—7、赔率均能解析；冠军浪漫勇士原值 1.1。这里只验证历史最终值，没有测试赛前反复刷新。
- 德国：结果表与名单表分别解析，未出赛马号 5、7；保留 `Abstand` 原文，不能直接改称“距冠军”。冠军原文 `Quoten zu 1 €: Siegwette 2,9` 与表内值一致。其他地区的分数赔率、派彩金额仍不能直接沿用此转换。
- 马匹历史：ミッキーファイト资料现在已有 2026 战绩。以 2025-07-02 帝王賞为入口，实际截取 2025-04-19、2025-02-23、2024-12-19、2024-10-02、2024-08-04 五场；本场与之后的战绩全部排除。这个马匹页未证明能取齐五场单胜赔率。
- HKJC 发现：公开列表这次仅返回 2026-10-25 的已关闭菊花賞赛日；使用其实际 date／venueCode 取得 18 匹逐马资料和赔率。它证明“发现列表 → 赛日数据”可以走通一次，未证明未来全年发现。进一步查询返回的马匹 ID，资料响应为空，不能标成六项基础信息已齐。
- HKJC 历史重取：2025 Cox Plate 的选定身份、逐马结果和结果状态与 10 月 22 日快照一致。来源 ID 是 `20251025S109`，显示场次却为 10，不能根据显示号码拼 ID。两个历史快照一致不证明新赛果或更正能及时获取。
- NAR 未来页：从首页实际链接取得 JBC Classic 出走予定页。页面注明截至 10 月 24 日的信息、10 月 29 日最终发表、10 月 30 日公布出马表／枠顺。应显示“待最终名单”，不能因为已有马名便开放购买。
- 美国：内嵌 JSON 虽没有 HTML 表格，仍可取得赛事元数据；其中 `isLive` 和 `isCompleted` 同时为真，不能只看 `isLive` 就判断可购买。需另外核验业务状态。

## 发布时间会限制小游戏可购买范围

[JRA 2026 即 PAT 发布时间表](https://www.jra.go.jp/dento/soku/instructions/hatsubai/jra.html)列出 GⅠ 前日发售窗口，自星期五 18:30 开始；这说明官方可售资料临近赛事才开放，**不证明 App 在这个时间一定能取得报价**。

[HKJC 2026 年 1 月转播安排](https://www.hkjc.com/english/pressrelease/mcs01_showhtml.asp?SelType=NEWS&filename=20260122_110129_E_NEWS.htm)则分别列出两组赛事的开售时刻，不能假设所有海外赛事均提前同样天数提供赔率。本轮没有证明“海外赛事都只有当天赔率”。

已确认的系统日期当日禁购、未来 30 天上限、最终确认名单与可信官方单胜报价条件均不改变。没有合格报价时，不能用预测值、文本冠军派彩或其他未核实市场的数字替代。

## 风险与下一阶段验收

| 问题 | 影响／证据把握 | 最小下一步 |
| --- | --- | --- |
| 403、页面外壳、空资料响应 | 高；本次观测明确，但不能外推永久不可访问 | 按机构继续验证正常公开路径／有说明的官方服务；保留明确失败状态，不绕过限制 |
| 未公布与获取失败混淆 | 高；JBC 页面明确尚未最终公布 | 分别保存待公布、抓取失败、解析失败、部分缺失；失败或空响应不代表官方删除名单，不自动退款 |
| 主／备用来源市场、马匹 ID 不一致 | 高；跨来源主键及市场语义仍未齐 | 保留真实来源 ID、市场、原值及成功时间；别按马名模糊合并，赔率别平均或静默替换 |
| 状态代码不等于正式确认合同 | 高；已取到字段，但所有状态枚举语义未核全 | 只有核实正式冠军及完整同着集合才交给结算；“RESULT”字样本身不足以启动正式钱包资金处理 |
| 历史样本代替持续更新证明 | 高；尚无发布前后连续观察 | 后续在用户触发的启动／详情／手动刷新窗口比较待公布→名单→赔率→正式赛果；保存前后版本，不新增定时轮询 |
| 数据获取时间被误当官方更新时间 | 中；不少来源无明确更新时间 | 分开记录最近尝试、最近成功获取、官方发布时间；未知官方时间保持未知 |

还需验证：各年度榜内赛事的目录覆盖、逐项赏金与口径、马匹六字段与截至该场前五次出赛、合格赛前 Win 报价与市场说明、正式赛果／同着／取消／更正的来源语义，以及缓存合并后的真实端到端更新。当前未进行全年度自动采集、官方授权采购或桌面应用实现。

## 界面选择（第 62 轮已确认）

1. 小店保留暂无最终名单／赔率的未来赛事，显示所有缺项，暂不可购买。

## 复现

只复核已保存证据、不会联网：`python3 check_saved_fields.py`。Notebook 可从本文件夹或项目根目录运行，仅使用 Python 标准库。

`probe_sources.py` 和 `probe_public_discovery.py` 是本轮有限请求脚本，重新运行会访问来源；后者复用相同的已保存查询结果，不应被用作新鲜度验证。脚本不是 App 的稳定适配层。
