# 第 70 轮：联动预览进入后没有赛事气泡

日期：2026-10-27。用户反馈选择英文后不显示气泡。本轮只修复导航预览的默认场景，不改变正式应用收集规则、赛事名称语言、布局或资金。

## 复现与原因

运行 `node research/check_welcome_race_visibility.mjs`，执行实际 welcome 表单事件、目标 URL 构造和首次收集组件初始化，并核对实际 CSS 隐藏条件。修复前，中、日、英三个默认入口都得到 0 个可见夹具气泡，英文断言失败。

原因是默认跳转写入 `collectionState=finding`。该场景表示尚无赛程，组件据此隐藏所有赛事卡；预览不会真实联网收集，因此不会自己离开此状态。它不是英文筛选造成的缺数据。

边界检查：同样年月下显式使用 `details`，三语的 `hasDates` 均为 true；年月始终保留为 2026／10；主赛事渲染没有按界面 `lang` 删除赛事的分支。因此只改默认场景即可，不修改筛选或赛程数据。

## 修复

- 语言选择后的默认导航预览改为 `details`，直接展示既有示例日期气泡及后台收集提示。
- 从设置重新预览首次启动也使用同一默认场景。
- 显式指定 `finding` 或 `offline-empty` 仍隐藏气泡，保留已确认的无资料语义；用户可从状态菜单主动比较这些场景。
- 布局及默认收起保持，版本号更新至 70 以刷新预览模块。

## 验证

回归命令修复后为 `en=2, zh=2, ja=2`，这里每组 2 个是测试 DOM 中的卡片夹具，不是实际月份赛事数量。显式无资料场景仍为 0，且显示场数待确认。

`check_preview_navigation.mjs` 与 `check_first_collection_preview.mjs` 继续通过，覆盖设置／缓存往返、暂停状态、默认收起及旧独立入口。没有新增临时调试日志或代码依赖；没有自动渲染浏览器，像素布局未据此声称通过。

新版入口：[语言选择与赛事可见性预览](http://127.0.0.1:8765/welcome.html?flow=preview&year=2026&month=10&v=70)。本项修复不等于 U2 整体评审通过，导航仍待用户继续核对。
