# 新赛事自动发现：固定入口到研究缓存

验证日期：2026-10-26，第 65 轮。目标是验证未来 App 可独立执行的发现逻辑，而非由助手临时搜索具体比赛网址。当前仍为研究程序，没有接入正式应用、设计页面或真实游戏钱包。

实现后续更新：2026-10-27 第 67 轮为同一发现程序补上 NAR 年度目录及介绍页／未提供详情链接的处理。以下 27 条及 14 次请求保留为第 65 轮当时的证据，不随代码变更重写。新年度与字段验证见[第 67 轮](../2026-10-27-japan/README.md)。

## 结论

**“不为每场比赛手填 URL，由程序发现新赛程并补充已公布资料”已在限定来源中跑通。** 各来源仍需预先编写网站适配器；尚不能承诺所有地区、未来年份及所有详细字段全部可自动更新，更不能承诺网站改版后零维护。

程序输入只有四个固定官方入口，以及用于筛选研究样本的当前日期：

- [Horse Racing in Japan 首页](https://japanracing.jp/en/)
- [NAR ダートグレード競走入口](https://www.keiba.go.jp/dirtgraderace/)
- [IFHA 排名目录](https://www.ifhaonline.org/default.asp?section=Racing&area=1)
- [Breeders’ Cup 首页](https://www.breederscup.com/)

实现中没有有马、菊花赏、天皇赏或 BCC 的赛事名、具体详情路径，也没有写死 IFHA 年度榜单的 batch 编号。程序运行不调用搜索服务、LLM、浏览器、登录凭据或外部脚本执行器。HTTP 及 HTML 解析复用项目已有工具；PDF 表格读取使用环境中已有的 pdfplumber，未安装依赖。

## 沿目录自动导航时发现的问题

日本首页 → 分级赛目录 → 年度列表入口的最后一层采用 JavaScript 年份跳转，普通 HTTP 不会自行执行它。适配器读取入口实际引用的 `redirect.js` 文本，检查其公开规则，再用电脑年份生成年度列表请求；不执行远端 JavaScript，不猜赛事路径。这个年份 URL 是**已核对的网站导航规则**，与“所有 URL 都来自普通 a 标签”不同。若规则改变则显式失败，不继续猜测。源站自身的往年回退循环没有在本轮实现。

只跟随目录中实际公布的当前年／未来两年链接。本轮只发现 2026 年，未构造或请求 2027、2028 年列表，因此不能声称已发现尚未公布的未来年度赛程。

IFHA 目录提供的 `www` 榜单地址本次 TLS 握手超时；同一目录中另一条**明确存在的绝对链接**成功。改用的是源站提供的链接，没有尝试访问控制绕过或自动无限重试。

育马者杯首页的预报名入口位于公开 `__NEXT_DATA__` JSON，普通 a 标签不足以发现。程序只把它当数据解析。预报名卡片中 Turf 的赞助链接指向 Classic；身份核对拦截了错配。正确的 Turf 详情链接解析仍待补充，当前只保留可核实的目录资料及异常状态，不借用 Classic 的字段。

## 对“11 月制作，12 月有马自动出现”的回答

有马的日期气泡目前就可从年度目录发现，不必等到出马表公布。随后每次启动、进入详情或手动刷新，正式采集器应重新检查该来源目录及已知赛事，发现新链接或字段后合并到同一场。获取失败时保留旧资料并显示已设计的异常提示；名单／赔率未满足购买条件时保持禁购。

本轮已经证明发现和合并机制可以纯靠本地程序执行，**尚未实际跨越 11—12 月的发布窗口**，也未完成所有阶段、所有地区的持续验证。不能把合成新增测试说成真实未来发布实测。正式实现还需要：

1. 各地区完整目录及历史新闻／详情的适配，避免首页滚动后漏失链接。
2. 稳定的跨年度赛事标识、别名匹配与返回赛事／日期／等级校验；本轮日本 key 仍为来源／年／名的研究标识，改名或跨年延期不能直接套用此 key。
3. 补齐海外匹配及被拒绝链接的正确解析、可用的最终出走和官方 Win 报价；不依赖赞助链接充当赛事详情地址。
4. 至少一次真实发布前后复验，再接入生产缓存、更新状态和资金逻辑；服务条款与长期访问条件也需随最终来源确认。

更新触发规则保持已确认决定：启动、进入详情、手动刷新；不新增定时轮询。已结束赛事的更正只在进入详情或手动刷新时复查。网站适配器可能需要维护，但不应因此要求用户每场手填 URL。
